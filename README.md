# glassgarden.cc

The website for glassgarden: generative ambient music, grown in small sealed worlds. Plain HTML, CSS and a little JavaScript, no build step, hosted on GitHub Pages.

## Pages

| file | what |
| --- | --- |
| `index.html` | home: the name, one sentence, a pixel jar that grows from a new seed on every visit, the four newest releases as small tiles (out or growing) and the newest notes |
| `releases.html` | everything out now, plus what's still growing |
| `garden.html` | what's growing: every script, instrument and piece in the works, by stage, rendered from `content/projects/` |
| `notes.html` | the field journal, rendered from `content/notes/` |
| `feed.xml` | RSS feed of the notes, generated by `npm run build` |
| `about.html` | the project, the approach, links |
| `404.html` | shown for missing pages |

Every page starts its `<head>` with the Google Analytics tag (`G-7WQ9X6GQVY`). Copy it into any new page.

## Content

Everything you edit lives as markdown in `content/`: one file per project and per note. Each file is YAML front matter (the data) between `---` lines, then the text. Edit, then run:

```sh
npm install        # once
npm run build
```

`tools/build.mjs` builds the whole site into `_site/`: the pages, `assets/` and `audio/` copied as they are, plus `data/releases.js`, `data/garden.js` and `data/notes.js` (which the pages load) and `feed.xml`, generated from the markdown. `_site/` is not committed: pushing to `main` runs the build in GitHub Actions and deploys it. To preview, run `make dev` (or `npm run dev`).

Files starting with `_` are not items. `order` sorts projects inside their stage (lowest first) and `releaseOrder` sorts the releases page (lowest first, so newest first); notes sort by `date`, with `order` only to break a tie on the same day.

### Projects: `content/projects/<slug>.md`

One file per script, instrument or piece, whether it's an idea or out. The file name is the slug and the `#anchor` (`releases.html#pollen`). `garden.html` is the public board of everything, after
[dessertplanet's dessert menu](https://dessertplanet.co/menu/): each project sits in one of five stages, drawn as a small pixel plant in the jar's palette.

| stage | means |
| --- | --- |
| `seed` | an idea, written down |
| `sprouting` | the first code, not played yet |
| `growing` | it plays, still being shaped |
| `bloom` | out, for anyone to use |
| `resting` | set aside for now |

Add `release: true` and the project also gets a card on `releases.html` and a home tile, and its title on the garden links to that card. Its stage sets the status: `bloom` is "out now", `growing` is "growing". The body is the summary, as plain text, used on both pages.

```md
---
order: 1                         # position inside its stage on the garden
title: pollen
stage: growing
kind: norns script · plays in the browser
home: vfm                        # optional: an instrument that comes out as Voltage Foundry Modular
href: /notes.html#something      # optional: where the title links (releases link to their card by themselves)
links:                           # first link is the main action
  - label: play in the browser
    url: https://...
checklist:                       # optional, shown on the garden: done and next
  - text: first run on a norns
    done: false

# only for projects on the releases page:
release: true
releaseOrder: 4                  # lowest first; newest first
year: "2026"
tags: [norns, browser]           # optional: what it runs on, shown as small chips
license: GPL-3.0                 # optional, shown with the year
credits: 'Built on <a href="https://...">someone's work</a>.'   # optional, one line of HTML
changes:                         # optional, newest first, folded under the card
  - date: "2026-11"
    text: what changed
audio: /audio/pollen-excerpt.mp3 # optional excerpt with a player
duration: "1:30"
seed: 3141                       # any whole number; each one grows a different jar
image:                           # optional: shown instead of the big jar, which becomes a small mark
  src: /assets/img/photos/pollen.png
  alt: what is in the picture, plainly
---

One or two sentences, as plain text.
```

When you go through the list, set `tended` (a date) in `content/projects/_garden.md`. When something comes
out, set `stage: bloom` and add the release fields.

When terrarium moves to this domain, change its link in `content/projects/terrarium.md`. Nothing else needs touching.

Excerpt audio goes in `audio/` (MP3 or M4A at 192 to 256 kbps keeps it small).

For scripts and tools, name the links the same way on every card: **play in the browser** for a playable
version and **view code** for the repository.

### Notes: `content/notes/<slug>.md`

Notes show in full on `notes.html`, and the newest three appear on the home page under "from the notes". The body is markdown, one paragraph per blank-line-separated block; raw HTML such as `<em>` or links also works.

```md
---
slug: 2026-11-modular            # used as the #anchor: notes.html#2026-11-modular
date: 2026-11-02
title: the modular
tag: gear                        # optional: field, patch, gear, release...
draft: true                      # optional: left out of the site and the feed until you remove it
links:                           # optional, under the text; the first is the main one
  - label: the rack on modulargrid
    url: https://www.modulargrid.net/e/racks/view/...
photo:                           # optional, one per note
  src: /assets/img/photos/modular.webp
  alt: What's in the photo, plainly.
  caption: where and when, lowercase
---

One paragraph per block, with [links](/releases.html#terrarium) and *emphasis*.
```

To add a photo, grade it first (see "Photos" in `brand/README.md`) so it's 4:5 and has no GPS in it.

Drafts are skipped by the build, so they never appear in `data/notes.js` or the feed. They do sit in `content/`, so don't put anything there you wouldn't publish if the repository is public.

#### Interactive notes

A note can carry a small interactive piece with `widget: isokey` in its front matter. Put the line `<!-- widget -->` in the body where it goes; paragraphs after that line are shown under it. The page that shows the note loads the widget's script (`notes.html` loads them all).

| widget | script | what |
| --- | --- | --- |
| `isokey` | `assets/js/isokey-grid.js` | a playable 16×8 grid with isokey's layout, scales and LED levels, and a soft voice |

## Publishing on GitHub Pages

`.github/workflows/pages.yml` builds the site and deploys it on every push to `main`. Only what is in `_site/` is published (the pages, `assets/`, `audio/`, the generated data and feed), not `content/`, so drafts stay private.

1. Create a repository (for example `glassgarden.cc`) and push this folder's contents to `main`.
2. In the repository: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. The `CNAME` file already says `glassgarden.cc`. At your domain's DNS add:
   - four `A` records for `@`: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - a `CNAME` record for `www` pointing to `<your-github-user>.github.io`
4. Back in **Settings → Pages**, wait for the DNS check to pass, then tick **Enforce HTTPS**.

If the domain is on Cloudflare, set those records to **DNS only** (grey cloud) until GitHub has issued the certificate.

## Previewing locally

```sh
make install   # once (or: npm install)
make dev       # or: npm run dev
```

This builds the site into `_site/`, serves it at <http://localhost:8000> (`make dev PORT=3000` for another port) and watches `content/`, the pages, `assets/` and `audio/`: when you save a file it rebuilds and the open page reloads. `make build` only builds, `make clean` empties `_site/`, and `make help` lists everything. Pages use root paths (`/assets/...`), which is why they need the server rather than double-clicking.

## Brand

Colors, type and spacing live as CSS variables at the top of `assets/css/site.css`. Type is IBM Plex Mono and IBM Plex Sans from Google Fonts. `assets/js/jar.js` is the pixel jar generator that drew the logo; the site uses its quieter palette.

The icons and share image in `assets/img` come from the brand kit: `brand/generator/gen_brand.py` writes `favicon-32.png`, `apple-touch-icon.png` and `glassgarden-mark.svg` there, and `og-image.png` is a copy of `brand/social/quiet/glassgarden-og-1200x630.png`. See `brand/README.md`.
